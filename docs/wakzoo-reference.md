# 왁주(wakzoo) 코드에서 가져올 만한 것

`wakzoo_code.zip` (GameMaker 디컴파일 코드 1,178개 + 문자열 표)을 읽고, 「용사가 다한다」에 옮길 만한 것을 추린 메모다.
2절의 항목은 모두 적용했다. 무엇이 어디에 들어갔는지는 바로 아래 표, 원래의 검토 내용은 1절부터다.

## 0. 적용 현황

| 항목 | 적용한 내용 | 수치를 고치는 곳 (`balance.json`) | 코드 |
| --- | --- | --- | --- |
| ① 소환 표식·웨이브 | 적은 0.6초 표식을 거쳐 나온다. 방마다 1~3 웨이브, 예산제. 폐광 짧게 / 요새 한 번에 많이 / 신전 조금씩 여러 번 | `zones[].waves`, `enemies[].cost`, `dungeon.spawnMarkTime` | `world/Waves`, `GameWorld.startWave` |
| ② 강화 개체 | 깊이 4 이상에서 확률로 등장. 같은 그림에 구역 색조·크기·수치만 다르다. 처치 몫은 방 돌파 보상에 더해 한 번만 지급 | `elite`, `zones[].eliteTint` | `combat/Enemy` |
| ③ 상자·제단 | 곁가지 방 한가운데. 상자는 방 돌파 후 한 번, 제단은 광물(신전은 체력도)을 바치고 축복 하나 — 쓰러지면 사라진다 | `zones[].branchFeatures`, `chestReward`, `shrine`, `blessings` | `model/Modifiers`, `GameWorld.useShrine` |
| ④ 탄 지우기 | 아래 정정 참고. 검기도 탄을 지우게 했고, 지워질 때 파편이 튄다 | — | `GameWorld.updateProjectiles` |
| ⑤ 무기 형태 | 철검 +5 넓은 마무리, +10 서리 검기 / 망치 +5 충격 내려찍기, +10 기절 내려찍기 | `weapons[].forms` | `Balance.FormDef`, `GameWorld.placeFormShapes` |
| ⑥ 상태 이상 | 빙결(쌓이면 얼어붙음)·기절·저주. 규칙 하나에 수치 세 줄 | `statuses` | `combat/Statuses` |
| ⑦ 연출 | 흔들림 약·중·강 세 값, 보스 사망 연출(1.2초 + 흰 번쩍임), 획득 알림 큐, 회피 먼지 | `feel` | `GameScreen`, `Hud.notice` |

**이후 바뀐 것 (플레이 피드백 반영):** ③의 상자는 "곁가지 방에 미리 놓인 것"에서 "방을 돌파하면 나타나는 것"으로, 제단은 "곁가지마다"에서
"구역마다 하나(광물 대신 골드를 바친다)"로 바뀌었다. 3절에서 "가져오지 않는다"고 했던 코인 경제는 골드로 들어왔다 — 다만 쓰는 곳은 제단 하나뿐이고 강화는 여전히 광석으로만 한다.
지금의 규칙은 `README.md` 가 기준이다.

**정정 (④):** 처음에 "충격파와 적 탄 사이에 상호작용이 없다"고 적었는데 틀렸다. 휘두른 무기와 충격파 판정에 닿은 탄은 이미 지워지고 있었다
(`ActionFeelTest.swordShattersProjectilesAndDodgeAvoidsThem`). 그래서 새로 넣은 것은 검기 판정과 파편 연출뿐이다.

**아직 손으로 확인하지 못한 것:** 수치는 규칙이 맞는지만 테스트했고(78개 통과), 난이도와 광물 경제는 실제로 플레이하며 맞춰야 한다.
방마다 적이 늘었는데 돌파 보상은 그대로이고, 상자와 제단이라는 새 수입·지출이 생겼다. 먼저 볼 값은 `zones[].waves.budget`, `chestReward`, `shrine.costMinerals` 다.

4절의 구조 원칙은 이렇게 지켰다.

- **효과는 수치 묶음이다.** 축복은 `Modifiers`(최대 체력·피해·회피·채굴 배율, 타격 시 상태 이상) 한 덩어리이고, 전투 코드는 축복의 이름을 모른 채 합쳐진 수치만 읽는다. 무기 형태도 `FormDef` 한 줄이 공격 하나를 통째로 정의한다. `if (축복 == …)` 같은 분기는 없다.
- **종류가 늘어도 코드는 늘지 않는다.** 상태 이상은 "게이지가 쌓이고, 가득 차면 일정 시간 발동"이라는 규칙 하나다. 새 상태는 `statuses` 에 한 줄 추가하면 된다.
- **흩어져 있던 것을 표로 모았다.** 탄 발사(감시자 3발, 보스 표식 5발, 내려찍기 10발 원형)는 코드의 `if ("mark".equals(...))` 에서 적·보스 공격 정의의 `shots` 로, 처치 파편 색은 `GameScreen` 의 `switch` 에서 `enemies[].color` 로, 화면 흔들림 다섯 값은 `feel` 의 세 값으로 옮겼다.
- **오타는 시작할 때 잡는다.** 형태가 가리키는 상태 이상, 제단이 가리키는 축복, 구역의 방 보상 종류가 실제로 있는지 `Balance.validate()` 가 검사한다.

아래는 적용 전의 검토 내용이다.

읽은 범위의 한계: 코드만 있고 그림·소리·방 배치 데이터는 없다. 직접 플레이해 본 것도 아니다.
그래서 아래는 "코드가 이렇게 동작한다"까지만 확인한 것이고, 손맛에 대한 판단은 플레이해 본 쪽의 기억이 우선이다.

## 1. 어떤 게임인가 (코드로 본 구조)

- 옆에서 보는 2D 총기 로그라이트. 점프·착지(`jump_mode`, `landingsmog_ob`), 구르기(`roll`), 엘리베이터로 층 이동(`elevator_ob`), 5개 스테이지 + 상점 방.
- 총 약 90종. 총마다 탄·이펙트 오브젝트가 따로 있고(`*_bullet_ob`, `*_effect_ob`), 수치는 `system` 의 `gun_list` 표에 모여 있다.
- 방 안에서 적이 **표식을 거쳐 여러 차례 소환**된다(`summonmark_ob`, `summon_count`).
- 소지품: 열쇠, 코인, 블랭크(`hollow`, 적 탄 지우기), 방어막, 패시브 아이템 130여 개, 펫.
- 방 사이 이벤트: 상점, 석상 7종(`*_statue_ob`), 뽑기 NPC, 감옥에 갇힌 NPC.
- 저주(`curse`) 수치: 높을수록 적이 강화되지만 일부 보상도 커진다.

우리 게임과 다른 점이 크다. 우리는 위에서 보는 근접 전투이고, 한 판짜리 로그라이트가 아니라 캠프로 돌아와 강화하며 세 구역을 뚫는 구조다.
따라서 총·탄약·재장전·층 이동은 가져올 게 없고, **방 하나를 재미있게 만드는 장치**와 **보상 방의 종류**가 쓸모 있다.

## 2. 가져올 만한 것 (추천 순)

세 공략 구역을 일부러 다른 스타일로 설계했으므로, 각 항목마다 "구역별로 어떻게 다르게 쓸지"를 같이 적었다.

### ① 소환 표식과 웨이브 — 가장 추천

왁주: 적이 바로 나타나지 않는다. 바닥에 표식이 먼저 뜨고, 애니메이션이 끝난 뒤 40프레임쯤 지나 빛 이펙트·소리와 함께 적이 나온다.
방에 남은 적과 표식의 합이 `min_monster` 이하가 되면 다음 무리를 부른다. 한 번에 부르는 양은 예산제(`floor(4 + level / 1.5)`)이고, 적 종류마다 예산을 다르게 깎는다(큰 적 2, 보통 1, 잡몹 0.2).

우리 현재: 방에 들어가면 `DungeonGenerator` 가 정해 둔 생성점에 2~4마리가 한꺼번에 서 있다. 한 번 치우면 끝이라 방이 짧다.

옮긴다면:
- 생성점에 0.6초쯤 표식 → 적 등장. 표식이 떠 있는 동안은 맞지 않고, 플레이어는 자리를 잡을 시간을 얻는다. 문 앞에서 바로 맞는 일도 사라진다.
- 방마다 1~3 웨이브. 남은 적이 1마리 이하가 되면 다음 웨이브. 소울나이트의 방 진행이 정확히 이 방식이다.
- 예산제는 `balance.json` 의 적 정의에 `cost` 하나만 추가하면 되고, 깊이에 따라 예산을 올리면 지금의 "깊이별 +1마리" 규칙을 대체한다.
- 구역별 차이: 폐광은 1~2 웨이브로 짧게, 요새는 웨이브 수는 적되 한 번에 많이(돌진병 떼), 신전은 조금씩 3 웨이브(감시자가 계속 보충).

손댈 곳: `GameWorld` 의 전투 시작과 방 완료 판정, `Balance.DungeonDef`, `WorldRenderer`(표식 그리기). 기획서 규칙 "전투가 끝나야 광맥을 캘 수 있다"와 충돌하지 않는다.

### ② 색만 바꾼 강화 개체 (저주 몬스터)

왁주: 일반 적이 `irandom(40) < curse` 확률로 저주 개체가 된다. 그림은 그대로 두고 붉게 칠할 뿐이다(`sp_color = 255`). 엘리트·지옥 변종도 같은 틀에 수치만 다르다.

우리 현재: 일반 적 그림이 슬라임·돌진병·감시자 3종뿐이다. 구역이 깊어져도 보이는 적이 같다.

옮긴다면: 깊은 방(예: `depth >= 6`)과 곁가지 보상 방에 일정 확률로 강화 개체. 체력·피해 배율과 색조만 다르고, 처치하면 광물을 조금 준다.
그림을 새로 그리지 않고 적 종류가 두 배가 된다. 구역별로 색을 다르게 하면(폐광 주황, 요새 파랑, 신전 보라) 구역 정체성도 강해진다.

손댈 곳: `Enemy`(배율·색 필드), `balance.json`, `WorldRenderer.drawEnemy`(이미 `batch.setColor` 로 예고 색을 입히고 있어 한 줄).

### ③ 곁가지 방에 "선택하는 보상" — 상자와 석상

왁주: 석상은 대가를 치르고 확률 보상을 받는 장치다. 예) 뱃지를 바치면 확률적 보상, 포인트 30으로 기도, 입 벌린 괴물 석상에 손 넣기. 뽑기 NPC, 할인 패시브가 붙는 상점도 있다.

우리 현재: 곁가지는 "광맥이 더 많은 방"뿐이다. 그리고 이번 에셋 정리에서 상자(`chest`, `chest_gold`) 그림은 장식으로만 남았다.

옮긴다면:
- **상자를 진짜 보상으로.** 곁가지 끝 방을 치우면 상자가 열리고 광물 묶음이 나온다. 광석과 같은 원칙이다 — 보상처럼 생긴 것은 실제로 보상이어야 한다.
- **석상 하나.** 광물 N개를 바치면 그 구역에서 죽을 때까지 유지되는 축복 하나(체력 +20, 회피 재사용 단축, 채굴 시간 단축 중 무작위). 죽으면 사라지므로 기획서의 "사망 시 실패한 방만 초기화" 규칙을 건드리지 않는다.
- 구역별 차이: 폐광은 상자 위주(재료 수급), 요새는 무기 거치대 석상(전투 축복), 신전은 묘비 제단(체력을 바치고 큰 보상 — 왁주의 저주식 위험/보상).

손댈 곳: `DungeonGenerator`(방 성격 하나 추가), `GameWorld` 상호작용, `GameState`(구역 축복). 강화 재료와 경쟁하는 광물 소비처가 생기므로 `BalanceTest` 의 경제 검증을 다시 봐야 한다.

### ④ 충격파가 적 탄을 지운다 (블랭크)

왁주: 블랭크(`hollow_ob`)는 반경이 프레임마다 20씩 80→640까지 퍼지며 닿은 적 탄을 지우고, 주변 180 안의 일반 적을 밀어내고, 화면을 흔든다. 보스는 밀리지 않는다.

우리 현재: 각성 충격파(Q)는 직선 피해 판정이다. ~~감시자와 보스가 쏘는 `Projectile` 과는 상호작용이 없다.~~ (틀린 서술. 0절의 정정 참고)

옮긴다면: 충격파 판정 상자에 닿은 탄을 지운다. 신전(감시자가 많은 구역)에서 충격파가 방어 수단도 되어 쓰임새가 둘로 늘어난다. 구현은 `GameWorld` 의 탄 갱신 루프에서 판정 상자와 겹치는지 한 번 더 보는 정도다.

### ⑤ 강화 단계에 따라 무기 "형태"가 바뀐다

왁주: 총 수치가 전부 형태(`g_form`)별 배열이다 — 위력, 연사 간격, 넉백, 탄 퍼짐, 한 번에 쏘는 수, 각도 차, 충전 시간. 같은 총이 형태가 바뀌면 다른 총처럼 쏜다.

우리 현재: 강화는 피해량만 올린다(`damagePerLevel`).

옮긴다면: +5, +10에서 형태가 바뀐다. 예) 철검 +5 = 3타째 범위 확대, +10 = 3타째에 짧은 검기. 망치 +5 = 내려찍기에 원형 충격, +10 = 기절.
"확률 강화를 계속 돌릴 이유"가 숫자 말고 하나 더 생긴다. `balance.json` 의 무기 정의를 `forms: [...]` 배열로 바꾸는 식이라 데이터 구조는 왁주 방식을 그대로 쓸 수 있다.

### ⑥ 상태 이상 — 특히 "쌓이는 빙결"

왁주: 빙결은 한 번에 걸리지 않고 게이지(`ice_gage`)가 차는 동안 이동·애니메이션이 점점 느려지다가 가득 차면 완전히 언다. 그 밖에 기절, 둔화, 화상, 독, 매혹(가장 가까운 다른 적을 공격)이 있다. `unstoppable` 인 적(보스)은 전부 무시한다.

옮긴다면: 구역 광물에 속성을 주는 방향과 맞는다. 요새(파랑) 광물로 만든 무기는 빙결 게이지를 쌓고, 신전(보라) 광물은 저주(받는 피해 증가)를 건다.
다만 지금은 광물이 한 종류라 범위가 크다. ⑤와 묶어 "형태가 속성을 연다"로 가는 것이 작게 시작하는 길이다.

### ⑦ 연출 — 값의 단계를 정해 둔다

- **화면 흔들림은 세 단계뿐**이다: 1(약), 5(중), 10(강). 코드 전체에서 이 세 값만 쓴다. 우리는 `GameScreen` 에 0.025 / 0.07 / 0.18 / 0.3 / 0.4 가 흩어져 있다. `balance.json` 에 약·중·강 세 값으로 모으면 조정이 쉬워진다.
- **보스는 등장·사망이 따로 있는 오브젝트**다(`*_summon_ob`, `*_death_ob`, 화면 흰색 번쩍임 `white_effect`). 우리는 등장 연출(`bossIntro`)은 있고 사망은 바로 보상이다. 사망 시 0.5초 정지 → 흰 번쩍임 → 파편 → 보상 순서만 넣어도 세 번의 보스전이 각각 마무리된 느낌이 난다.
- **획득 알림 큐**(`message_queue`): 아이콘 + 두 줄 설명이 차례로 뜬다. 우리는 "광물 +2" 떠오르는 글자뿐이라, 첫 무기 제작·지름길 개방·강화 상한 해제 같은 큰 사건에 같은 방식의 알림을 쓰면 좋다.
- **구르기 착지 먼지**(`landingsmog_ob`)처럼 동작 끝에 작은 이펙트를 붙이는 습관. 우리 회피(K)에는 잔상만 있다.

## 3. 가져오지 않을 것

| 왁주 | 이유 |
| --- | --- |
| 총 90종, 탄약·재장전 | 우리는 근접 무기 2종 + 강화가 축이다. 종류 수로 승부하지 않는다 |
| 점프·중력, 엘리베이터 층 구조 | 위에서 보는 한 장짜리 던전과 맞지 않는다 |
| 한 판 로그라이트(죽으면 처음부터) | 기획서의 캠프 귀환·지름길·침대 구조와 반대다 |
| 패시브 130종, 펫 | 지금 규모에서는 ③의 축복 3~5개로 충분하다 |
| 코인 경제와 상점 | 화폐는 광물 하나로 유지한다. 둘이 되면 강화 경제가 흐려진다 |

## 4. 구조에서 배울 점 (반면교사)

- `system` 오브젝트 생성 코드가 23만 자, 플레이어 스텝이 6만 6천 자다. 패시브 효과는 `ds_list_find_index(system.passive_item_list, 101) >= 0` 같은 **번호 검사가 코드 곳곳에 박혀 있다.** 아이템 하나를 고치려면 전체를 뒤져야 한다.
- 우리는 수치를 `balance.json` 에, 규칙을 `model`·`world` 에 나눠 두었고 화면 없이 테스트한다. ③의 축복이나 ⑤의 형태를 넣을 때도 "효과 = 데이터의 배율 묶음"으로 두고, `if (축복 == 3)` 식의 분기를 전투 코드에 넣지 않는 것이 이 구조를 지키는 길이다.
- 반대로 왁주가 잘한 것: 총 한 자루를 **수치 20여 개의 한 줄**로 정의해서 총을 늘리는 비용이 작다. 우리 적·보스 공격도 같은 방향(`bossAttacks`)이므로, ①의 웨이브도 코드가 아니라 표로 정의하는 편이 맞다.

## 5. 순서 제안

1. ① 소환 표식 + 웨이브 — 방의 길이와 리듬이 바뀌는 가장 큰 변화. 다른 항목의 바탕이 된다.
2. ② 강화 개체 — 작은 작업으로 적 다양성 확보. ①의 예산제에 바로 얹힌다.
3. ④ 충격파로 탄 지우기, ⑦ 보스 사망 연출 — 각각 반나절 규모.
4. ③ 상자·석상 — 경제에 영향이 있으니 수치 검증과 함께.
5. ⑤ 무기 형태 → ⑥ 속성 — 강화 시스템의 다음 단계. 기획서 개정이 필요하다.
