# 11월 이동·가림 검토의 게임 적용

통합 기준: `main`의 `c8df37c` (PR #24 폴더 분리 + PR #25 전투 변경).
작업 브랜치: `haeseong/layers-integrated`. 이동 마스크 재생성의 원본 기준은 `123438a899a56999439da1e6c2212ee880a210a2`로 고정한다.
검토 자료만 보관하는 작업이 아니라 실제 이동 마스크와 렌더러에 적용한 변경이다.

## 적용 내용

- 검토 원본 73장 중 이동 표시가 있는 39장의 `assets/walkmask`를 갱신했다.
- 가림 수정이 있는 46장은 `assets/data/reviewed-occlusion.json`과 개별 마스크 199개로 연결했다 (초기 통합본 85개에서 물체별로 분리). 원화 PNG의 크기·색·위치는 바꾸지 않았다.
- 기존에는 없던 통로 가림을 지원한다. 방·통로·연결부 모두 같은 원화 좌표로 가림을 적용하며 좌우 반전도 함께 처리한다.
- `behind`는 물체 밑동의 월드 Y로 용사·몬스터와 정렬하고, `always`는 앞쪽 테두리처럼 마지막에 그린다. 수정한 장면의 예전 가림은 중복해서 그리지 않는다.
- `erase-layer`는 앞서 존재한 모든 가림에 적용한다. 그 뒤에 그린 새 가림은 유지한다. 비활성 표시와 기존 레이어의 모드·깊이 변경도 반영했다.
- 연결부가 원래 그림을 덮는 곳과 가장자리 혼합 영역을 가림에 중복 사용하지 않는다. 화면에서 멀어진 가림 텍스처는 해제한다.

## 붓질에서 추가로 다듬은 부분

`refinements.json`에 원본 검토와 구분해서 기록했다.

- 성채 `exit-R1-R2`: 높은 기둥의 몸통 대신 밑동만 충돌시킨다. 뒤쪽 계단 진입 바닥을 막던 문제를 해소했다.
- 광산 `exit-L1-L2`: 난간 밑동과 실제 기둥·바위 실루엣을 따라 조정했다. 오른쪽 맨바닥에서 용사가 세로로 잘리던 가림을 줄였다.
- `citadel-crossing`, `tower-stair-bend`: 기존 통과 경로를 침범하던 붓질을 난간·기둥 밑동으로 한정했다.
- `tower-bridge`: 주요 기둥 네 개와 앞 난간을 다각형 윤곽으로 다듬었다.
- 광산 방의 광차: 본체·바퀴 윤곽과 접지 깊이를 맞췄다.
- `entry-R2-R7`, `exit-T7-T6`: 새 충돌 경계 옆 벽면에 고립된 이동 픽셀을 정리했다.
- `rooms/tower`의 약 `(0.28, 0.345)` 바닥은 `entry-T3-T5` 연결부가 덮는다. 방 마스크만 열어서는 실제 이동이 막혀 있어, 연결부의 같은 포장 바닥도 열었다. 원화의 난간·기둥을 열지 않도록 범위를 한정했다.

미확정인 `rooms/tower-ore-a`, `rooms/mine-mob-c`의 이동 마스크는 기준 커밋과 바이트 단위로 동일하다. 메모에 남긴 애매한 홈·잔해는 임의로 열지 않았다. 전투 문 잠금, 보스 북쪽 귀환문 규칙, 전투 수치는 변경하지 않았다.

## 자료와 재생성

- `feedback.json`: 전달받은 검토 JSON 원본.
- `reviewer-notes.md`: 전달받은 검토 메모 원본.
- `refinements.json`: 실행·그림 검증에서 추가로 조정한 경계.
- `tools/apply_layer_review.py`: 원본 검토와 보정값으로 런타임 마스크를 재생성한다. Python과 Pillow가 필요하며 게임 실행에는 필요 없다.

저장소 루트에서 `python tools/apply_layer_review.py`를 실행한다. 원화 해시·크기·경로와 기존 가림 정의를 먼저 검사한다. 이동 마스크는 위 기준 커밋의 파일에 검토를 다시 적용하므로 반복 실행해도 결과가 같다. 기준 커밋이 없는 얕은 clone에서는 해당 커밋을 먼저 받아야 한다.

`make_walk_masks.py --force`나 이전 `apply_walk_mask_review.py`로 이동 PNG를 다시 만든 경우에는 마지막에 이 스크립트를 실행해야 한다. 원화나 기존 가림 정의를 바꿨다면 검토 데이터도 다시 확인해야 하며, 검사 오류를 우회하지 않는다.

새로운 디자인 초안·HTML·대형 검토 캡처는 `design/`에만 두었으며 이 PR에는 포함하지 않는다. 런타임에 필요한 가림 마스크 총량은 약 132 KiB이다.

## 물체별 가림 및 흑백 PNG 디코딩 수정 (2026-11-15)

**실제 원인:** libGDX는 8비트 흑백 PNG를 `Pixmap.Format.Alpha`로 읽는다. 이 형식의 검은 마스크 픽셀도 RGB는 흰색이고 알파만 0이다. 예전 코드는 빨강 채널만 읽어 255로 판단했으므로, 투명해야 할 곳까지 잘라낸 사각형 전체가 용사 위에 그려졌다. 이제 밝기 × 알파로 가림 값을 구한다. `ImageIO`만으로 파일을 확인하던 검사에 더해 실제 게임의 네이티브 PNG 디코더를 회귀 테스트에서 실행한다.

- 같은 모드·깊이여도 서로 다른 물체를 합치지 않는다. 원본 레이어 ID와 붓질 ID를 각각 보존해 46개 장면을 199개 조각으로 분리했다.
- `objects.json`에는 광산 가로 통로·철로 굽이·광산 연결부, 성채 교차 통로, 탑 다리·계단 굽이 **6개 장면 / 44개 실루엣**을 기록했다. 기둥·광차·난간과 옆의 빈 바닥을 구분한다. 모든 46개 장면을 수작업으로 재추적했다는 뜻은 아니다.
- 긴 경사 난간 10개에는 `depthLine`을 넣었다. 원본 X 위치별 밑동 깊이로 정렬하며, 하나의 텍스처를 공유하는 4픽셀 폭 조각으로 그린다. 좌우 반전 시 원본 좌표와 가림 깊이도 함께 대응한다.
- F1 초록 이동 표시는 바닥 다음, 용사·몬스터 이전에 그린다. 검토용 표시가 용사를 초록색으로 덮지 않는다.
- 원화 및 이동 마스크는 이번 추가 수정 전과 동일하다. 검토 JSON 원본도 수정하지 않았다.

검증 기록:

- 게임의 네이티브 디코더로 모든 마스크의 검은색·흰색·중간 투명도를 확인한다. Java `ImageIO.getRGB`의 회색→sRGB 변환값 대신 PNG 원시 회색 샘플을 비교한다.
- `LayerObjectSmokeLauncher`는 광산 빈 바닥, 광차 앞뒤, 성채·탑 난간, F1 표시의 15개 위치를 캡처한다. 일부 앞뒤 정렬 검사는 의도적으로 이동 불가 위치에 용사를 놓으며, 각 위치의 `walkable` 여부를 로그에 남긴다.
- 광산 `mine-traverse`의 `(0.38, 0.55)`, `(0.571, 0.676)`은 실제 `WorldMap.free(...,9,6)`가 참인 바닥이다. 이전 렌더러에서 용사가 사라지는 것을 재현하고 수정 후 정상 표시를 확인했다.
- 마스크·매니페스트·이동 PNG 273개를 재생성했을 때 해시가 동일함을 확인했다.
- 캡처와 비교 이미지는 로컬 `design/layer-detail/`에 보관하고 Git에는 올리지 않는다.

최종 검증: Java 17 빌드 성공, JUnit **230/230 통과** (네이티브 PNG 디코더 검사 포함). 실제 OpenGL 전체 장면·깊이 위치 **131개**와 물체별 비교 위치 **15개**를 캡처했다. 사람의 전 구간 수동 플레이 검증을 대신하는 수치는 아니다.
