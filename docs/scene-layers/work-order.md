# 작업 지시 — 용사가 다한다: 앞뒤 가림을 "층으로 나눈 그림" 방식으로 다시 만들기

## 0. 왜 다시 하는가
현재 `haeseong/layers-integrated` 브랜치의 가림은 원화 한 장에서 검토용 붓 자국(둥글고 대략적인 표시) 모양대로 픽셀을 잘라 용사 위에 다시 그리는 방식이다. 붓 자국이 물체 윤곽과 맞지 않아서 다음 문제가 생긴다.
- 물체 옆 맨바닥까지 같이 잘려 용사 위에 덮인다. 용사가 바닥에서 잘리거나 통째로 사라진다.
- 물체 가장자리가 덜 덮여 용사가 기둥을 뚫고 나온 것처럼 보인다.
- 이동 영역이 담·테두리 위까지 열려 있어 용사가 담 위에 올라선 것처럼 보인다.

검토 JSON(`docs/layer-review/feedback.json`)의 붓질은 "여기에 이런 가림이 필요하다"는 위치 요청일 뿐이다. 실제 판정이나 가림 모양으로 쓰지 않는다.

## 1. 목표 방식 (실제 탑다운 2D 게임 방식)
장면마다 그림을 아래 세 층으로 나눈다.

1. **바닥 그림**: 지금 원화를 그대로 쓴다. 원화 파일은 수정하지 않는다.
2. **물체 층**: 용사가 앞뒤로 돌아갈 수 있는 물체 하나하나를 **투명 배경 PNG**로 오려낸다. 기둥, 울타리 말뚝, 등불·촛대, 화로, 광차, 나무, 통·항아리·상자, 아치 기둥, 바닥 안에 선 바위 등이 해당한다.
3. **앞 테두리 층**: 화면 아래쪽(남쪽) 앞벽·난간·절벽·바위 테두리처럼 용사가 그 앞으로 갈 수 없는 것을 PNG 한 장으로 오려낸다. 항상 용사 위에 그린다.

그리는 순서: 바닥 그림 → (물체 층 + 용사 + 몬스터 + 투사체를 **밑동 Y로 정렬**) → 앞 테두리 층 → UI.

## 2. 오려내기 규칙 (그림 작업)
- 물체 PNG와 앞 테두리 PNG는 **원화와 같은 가로·세로 크기의 캔버스**로 만든다. 원화와 같은 위치의 픽셀을 **색 변경 없이 그대로 복사**하고, 나머지는 완전히 투명(알파 0)이다. 이렇게 하면 위치 좌표가 따로 필요 없다.
- 윤곽은 물체의 실제 외곽선을 정확히 따른다. 바닥·그림자·주변 자갈은 포함하지 않는다. 가장자리는 원화의 외곽선 픽셀까지만 포함하고 1~2px 이상 바깥으로 번지지 않는다(후광 금지).
- 물체 바로 아래 바닥에 떨어진 그림자는 바닥 그림에 남긴다. 물체 층에 넣지 않는다.
- 다른 물체에 일부가 가려진 물체는 원화에 보이는 부분만 오려낸다. 가려진 부분을 새로 그리지 않는다.
- 한 PNG에는 물체 하나만 넣는다. 밑동 높이가 다른 물체를 합치지 않는다. 길게 비스듬한 난간처럼 밑동이 위치마다 다른 물체는 2~4개 구간으로 나눠도 된다.
- 원화(`assets/scenes/**`)와 색감·해상도·화풍은 바꾸지 않는다.

## 3. 데이터 형식
파일 위치:
```
assets/layers/<kind>/<sceneId>/front.png          앞 테두리 (없으면 생략)
assets/layers/<kind>/<sceneId>/<objectId>.png     물체 하나당 한 장
```
`<kind>`는 rooms / passages / joints, `<sceneId>`는 기존 장면 ID(예: central-camp, tower-bridge, entry-L3-L4).

목록 파일 `assets/data/scene-layers.json`:
```json
{
  "version": 1,
  "scenes": {
    "rooms/central-camp": {
      "front": "layers/rooms/central-camp/front.png",
      "objects": [
        { "id": "arch-blue-left-pillar",
          "image": "layers/rooms/central-camp/arch-blue-left-pillar.png",
          "foot": 0.512,
          "block": [0.300, 0.495, 0.335, 0.515] }
      ]
    }
  }
}
```
- `foot`: 물체가 바닥에 닿는 선의 세로 위치(원화 기준 0~1, 위가 0). 용사 발이 이 선보다 위(북쪽)면 물체가 용사를 덮고, 아래(남쪽)면 용사가 물체를 덮는다. 비스듬한 물체는 `footLine: [[x, y], [x, y], ...]`로 위치별 밑동을 줄 수 있다.
- `block`: 밑동 충돌 상자 [x0, y0, x1, y1](원화 기준 0~1). 그림 전체가 아니라 바닥에 닿는 밑동만 막는다. 걸어서 지나갈 수 있는 낮은 물체는 생략한다.
- 좌우 반전으로 배치되는 방·통로도 원화 기준 좌표로 적는다. 반전은 코드가 처리한다.

## 4. 이동 영역 규칙 (assets/walkmask)
- 이동 영역은 **앞 테두리 바로 뒤에서 끝낸다.** 용사가 담·난간·절벽 위나 속에 설 수 없어야 한다.
- 물체는 `block` 상자로 막는다. 이동 마스크에 물체 전체 실루엣을 검게 칠하지 않는다.
- 평평한 선로·돌계단·다리 상판은 통과, 목재 가대 위 고가 선로는 막힘.
- 장식용 입구, 전투 문 잠금, 진행 조건은 바꾸지 않는다.
- 바닥보다 확실히 높게 그려진 단(층계참, 선반 바닥)으로 올라가는 길에 계단이나 경사로가 그려져 있지 않으면, 임의로 열지 말고 "경사로 그림이 필요한 곳" 목록에 적는다. 그림 추가는 해성님 승인 후에만 한다.

## 5. 코드 작업
1. 기준 브랜치: 최신 `haeseong/game`에서 새 브랜치를 만든다(예: `haeseong/scene-layers`). `main`에 직접 올리지 않는다. 작업이 끝나면 PR로 올린다. 커밋 작성자는 `choicomet <choihaesung627@gmail.com>`.
2. `haeseong/layers-integrated`에서 가져올 것: 이동 마스크 수정분, 통로·연결부에도 가림을 그리는 구조, 좌우 반전 처리, 흑백 PNG 알파 디코딩 수정, 연결부 겹침 구간 처리.
   가져오지 않을 것: 붓 자국으로 만든 가림 마스크(`reviewed-occlusion.json`과 그 마스크 PNG들). 새 층 그림이 들어간 장면에서는 붓 자국 가림과 예전 `scene-occlusion.json` 가림을 모두 끈다(같은 물체가 두 번 그려지지 않게).
3. `scene-layers.json`을 읽어 물체 층은 용사·몬스터와 `foot` 기준으로 정렬해 그리고, 앞 테두리는 마지막에 그린다. `block`은 이동 판정에 넣는다.
4. 이미 있는 큰 방의 앞 레이어(`assets/scenes/natural-v1/*-front.png`: mine, citadel, tower, seal-hall, mine-mob-b, mine-mob-c, mine-ore-a, mine-ore-b, mine-boss-a, citadel-boss-a, tower-boss-a)는 앞 테두리로 그대로 재사용한다. 그 방들은 물체 층만 추가한다.
5. F1 개발 메뉴에 "가림 층 보기"를 추가한다. 각 물체 윤곽과 밑동 선을 표시하는 확인용이다.

## 7. 확인 방법과 결과 보고
- 물체마다 용사를 **앞(남쪽), 뒤(북쪽), 왼쪽, 오른쪽**에 세운 실제 게임 화면 캡처로 확인한다. 몬스터 한 마리도 같은 방식으로 확인한다.
- 위 캠프 스크린샷 3곳과 동굴 뒤쪽 길은 반드시 전후 비교 캡처를 남긴다.
- 기존 이동 연결성 테스트(DungeonWalkabilityTest 등), 출입구 양방향 이동 테스트, 전투 문 잠금 테스트가 모두 통과해야 한다.
- 실패 기준: 맨바닥에서 용사가 잘림 / 기둥 뒤에서 용사가 앞에 보임 / 물체 밖으로 바닥이 같이 덮임 / 담·테두리 위에 용사가 올라섬 / 같은 물체가 두 번 그려짐.
- 보고할 것: 장면별로 만든 PNG 목록, 전후 캡처, "경사로 그림 필요" 목록, 판단 못 한 곳.
- 우선순위 A를 끝내면 먼저 보고하고 확인받은 뒤 B, C를 진행한다.
