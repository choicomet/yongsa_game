현재 `codex/*` 원격 브랜치 13개는 삭제 완료했다. `claude/project-thread-q0jrky`, `claude/team-integration-m9u9aa` 두 개는 자동 승인 검토가 팀 공용일 가능성을 지적하여, 해성 소유로 삭제할 대상인지 사용자 확인을 기다리는 동안 임시 보존한다. 두 브랜치의 내용은 이미 통합본에 포함되어 있다.

김선우의 이전 작업은 이미 팀 통합 이력에 포함되어 있다. 현재 별도 원격 브랜치가 없으므로 임의로 만들거나 담당자를 재지정하지 않는다. 표의 담당자는 브랜치를 관리하는 사람이며, 그 브랜치의 모든 코드·그림을 혼자 만들었다는 뜻은 아니다. 원래 커밋과 저자 이력은 유지한다.

## 앞으로 작업할 때

1. 현재 폴더와 브랜치, 미커밋 변경, GitHub 최신 상태를 확인한다. 다른 사람이 사용하는 폴더의 브랜치를 임의로 전환하지 않는다.
2. `haeseong/game`의 기존 변경을 포함한 상태에서 작업한다. 별도 작업 폴더가 필요해도 기능별 원격 브랜치를 만들지 않는다.
3. 코드·그림·적용 내역을 함께 커밋하고 `haeseong/game`으로 올린다. 열려 있는 누적 PR을 갱신한다. 그 PR이 병합/종료된 경우에도 동일 브랜치를 계속 쓰며, 새 PR이 필요하면 현재 누적 범위로 작성한다.
4. 작업별 검증을 마치고, 그림 시안만 저장한 것과 게임에 적용한 것을 구분해 기록한다.
5. 팀원 브랜치와 `main`은 별도 요청이나 합의된 병합 절차 없이 삭제·덮어쓰기하지 않는다.

## 가져오기와 로컬 폴더

다른 체크아웃에서 처음 받을 때(미커밋 변경이 없는지 먼저 확인):

```powershell
git fetch origin --prune
git switch --track origin/haeseong/game
```

이미 `haeseong/game`을 사용하고 있다면 `git pull --ff-only`로 갱신한다. `main`에서 `pull`해도 아직 병합되지 않은 해성 작업은 받지 않는다.

현재 Codex 컴퓨터의 통합 작업 폴더는 `work/yongsa-haeseong`이다. 같은 Git 저장소의 별도 worktree이므로 `work/yongsa-source`에서 같은 브랜치로 다시 전환하려 하면 이미 다른 worktree에서 사용 중이라는 안내가 나올 수 있다. 이 컴퓨터에서는 통합 폴더에서 실행한다.

```powershell
cd work/yongsa-haeseong
.\gradlew.bat run
```

기존 `work/yongsa-source`의 게임 파일과 실행 파일은 이번 정리에서 교체하지 않았다. 거기서 실행하면 기존 PR #15 상태가 보인다. 이 폴더는 `7be4428`의 고정 미리보기(detached HEAD)로 남겼으며, 이후 수정과 실행은 `work/yongsa-haeseong`에서 한다. 통합 이력에 포함된 로컬 중간 브랜치 8개도 삭제했다. GitHub 브랜치 삭제 자체는 로컬 게임 파일을 바꾸지 않는다.
