# 방 사이 길 그림 — 2026-10-15

Claude의 `docs/ART_REQUESTS.md` 0-9에 따른 첫 16장입니다. 내장 imagegen으로 생성했고, 방 그림을 화풍 참고로 사용했습니다. **아직 게임 연결 전이며, 아래 보정 항목 때문에 검토용 초안입니다.** core/lwjgl3/맵 JSON은 변경하지 않았습니다.

## 파일과 배치

`assets/scenes/passages/`에 캠프(camp), 갱도(mine), 성채(citadel), 탑(tower)별 h/v/bend/ground를 넣었습니다.
- h: 왼쪽 ↔ 오른쪽. 출구 중심은 이미지 높이의 약 50~55%.
- v: 위 ↔ 아래. 출구 중심은 이미지 너비의 약 50%.
- bend: 위 ↔ 아래 S형. 위 출구는 약 x=0.70. 아래는 citadel/tower 약 x=0.30, mine/camp 약 x=0.50. 프롬프트 좌표를 실제 출구 좌표로 사용하면 안 됩니다.
- ground: 방/길 바깥 공간을 메우는 비보행 지형 후보.

실제 픽셀 크기는 `inspection.json`에 있습니다. 요청 해상도와 생성 해상도가 달라 원본 크기를 그대로 보관했습니다. 가로 그림은 약 3:1, 세로 2:5, 굽은 길 2:3입니다. 배치 시 원래 통로 길이는 유지하고 장식 영역·바닥 다각형은 실제 그림에서 따야 합니다.

## 반드시 남아 있는 보정 / 연결

1. **폭 3칸:** citadel-v/tower-v의 계단과 camp-v의 목재 데크는 외곽 폭 6칸에 그대로 넣으면 최소 3칸보다 좁아집니다. 일부 h도 그림 전체 높이 5~6칸으로 배치하면 바닥 폭이 부족합니다. 바닥 폭을 확장하는 그림 수정 또는 배치 영역 조정이 필요합니다. 충돌 폭만 넓혀 벽 위로 걷게 만들면 안 됩니다.
2. **ground 이음매:** 반복용으로 요청했지만 반대편 가장자리 픽셀이 일치하지 않습니다. 단순 Repeat로 쓰면 경계가 남을 수 있습니다. `inspection.json`에 경계 RGB 차이를 기록했습니다. 이음매를 손보거나 겹침 블렌딩을 적용한 뒤 사용해야 합니다. 무결점 타일로 검증된 상태가 아닙니다.
3. **Claude 담당:** 실제 바닥 다각형, 출구 위치, 맵 연결, 방과 길의 경계 처리 및 게임 내 검증.
4. 긴 특수 연결 L3↔L4와 T3↔T5는 이번 최소 12장 범위 밖입니다. 회전만으로 출구가 맞는다고 가정하지 마세요.
