- PNG 전체 UV 범위, 월드 표시 크기, 기존 103개 그림의 world 대응, 투명 여백 검사.
- 단일 판정·재료 소모: 긴 프레임에서도 최종 타격 완료를 한 번만 보고. 실제 모델의 성공/유지/하락/파괴 결과를 그대로 표시.
- lwjgl3:dist 실행 JAR 빌드 통과.
- git diff --check 확인.

현재 Windows/JDK17의 Gradle 테스트 worker @argfile이 한글 사용자 경로의 클래스를 읽지 못했다. 로컬 검증에서는 테스트/메인 .class 디렉터리만 영문 Gradle 캐시 경로로 복사하는 임시 init script를 사용했다. 저장소 코드나 테스트 기대값을 바꾸지 않았으며 테스트의 작업 폴더와 입력 데이터는 저장소 원본이다. 일반 경로에서는 표준 gradlew :core:test를 사용한다.

## 실제 GL 실행

VisualSmokeLauncher는 숨겨진 libGDX 창에서 실제 게임 프레임을 저장한다. 웹 목업이 아니다. 21개 시나리오와 타격 순간 1장, 총 22장을 캡처했다. 별도 QA 저장 폴더를 사용한다.

검증한 입력:
- 제작 시 광물 8개 소모와 무기 추가.
- +6 파괴 확인창 취소 시 상태와 비용 유지.
- 가방 장착 및 긴 인벤토리의 키보드 스크롤.
- 성공 / 유지 / 하락 / 파괴 / +10 각성 각각 실제 강화 서비스 결과 발생.
- 강화 중 Enter 연타, Esc, F1, 마우스 탭 입력 차단.
- 긴 프레임에서도 1회 시도만 처리, 비용/파괴 환급/성검 자동 장착 확인.
- 즉시 저장 파일에서 시도 횟수·광물·장착 무기 확인, 결과 연출 종료 후 입력 잠금 해제.
- 1280×720 및 960×540 대장간 레이아웃.
- 비교 갤러리의 상태 선택과 실제 캡처 표시를 브라우저에서 확인.

실행:
```powershell
.\gradlew.bat :core:test :lwjgl3:dist
java -jar lwjgl3/build/libs/yongsa-game-0.1.0.jar --visual-check <output-directory>
```

## 시각 검수

- 용사 발 기준과 6포즈 크기, 적의 시트 간격, 소품 가장자리 잘림 수정.
- 대장간 용사와 화로가 겹치던 첫 배치를 별도 작업 공간으로 교체. 모루 위 검과 망치 타격 위치 확인.
- 기본 검/각성 검의 실루엣, 캠프·갱도·성채·탑·최종 보스, 가방 상세 그림 유지 확인.
- 최종방 캡처에서 보스 일부가 HUD 아래로 들어가는 것은 기존 카메라·HUD 배치의 후속 검토 사항이다. 카메라와 전투 밸런스를 이번 그래픽 변경에서 조정하지 않았다.
- 정적 캡처와 입력 검증이며 전체 던전 완주·장시간 프레임 안정성 검증을 뜻하지 않는다.

내장 image_gen으로 생성했으며 원본 PNG를 재샘플링하거나 색상 변환하지 않았다. 프롬프트 및 레이아웃 수정 프롬프트는 PROMPTS.json에 기록했다.
