# 자연스러운 던전 · 배경과 Java 연결 준비

2026-10-11. 사용자가 캠프 참고 이미지와 같은 자연스러운 공간 구성을 던전에도 적용하고, 구상안의 모습을 실제 게임에 가깝게 유지하도록 요청했다.

**현재 결과는 게임용 배경 4장 + 좌표 데이터 + 별도 Java 이동 미리보기다. 본 게임의 방 연결·전투·문·채굴에 연결한 완료본은 아니다.** Claude가 진행 중인 방 구조 변경에 사용할 수 있도록 WorldMap, GameScreen, WorldRenderer, map.json은 이번 추가 작업에서 수정하지 않았다.

## 그림과 게임을 연결하는 방식

방 전체를 1672×941 PNG 한 장으로 그린 뒤 기존 용사·검·몬스터·공격 예고·효과를 별도로 올린다. 타일로 그림을 재조립하지 않아 시안의 구도, 벽의 불규칙한 윤곽, 광원 위치를 가깝게 유지할 수 있다. 기존 게임의 2번 스타일 용사와 분리된 검을 실제 Java/libGDX 렌더링으로 확인했다.

배경 속 용사·박쥐·마족병·마왕은 제거했다. 광차, 갑옷 전시대, 석상 같은 고정 장식은 남아 있다. 전경 벽은 이번 버전에서 통과할 수 없는 경계 밖에 두며, 독립된 앞쪽 가림 레이어는 아직 없다. 나중에 벽 뒤로 걸어가는 동선을 허용하려면 해당 벽을 분리해야 한다.

네 장은 대표 공간 템플릿이다. 모든 일반방·광물방·보스방에 자동 배정하지 않는다. 같은 그림을 모든 방에 반복하면 탐험 구분이 약해지므로 이 구조를 기준으로 출입구 방향과 용도별 변형을 추가한다.

## 좌표 계약

- JSON의 모든 점은 이미지 왼쪽 위를 (0,0), 오른쪽 아래를 (1,1)로 두는 정규화 좌표다. x는 오른쪽, y는 아래로 증가한다.
- 게임 월드는 기존처럼 y가 위로 증가한다. 배경 왼쪽 아래 월드 좌표를 (ox,oy), 그릴 너비를 W로 두면 H = W × 941 / 1672.
- 변환: worldX = ox + u × W, worldY = oy + (1-v) × H. 종횡비를 찌그러뜨리지 않는다.
- 미리보기의 시작 크기는 너비 26타일 × 타일32px = 832월드px, 높이 약468.25월드px다. 이는 확정 방 크기가 아니다. 보스전 공간을 늘리면 캐릭터 배율이 아닌 배경의 월드 크기와 맵 cell 간격을 함께 검토한다.
- walkable은 발이 놓일 수 있는 경계 초안이다. 주변 장식 안으로 발이 들어가지 않도록 보수적으로 작성했다. 화면에 선을 켜 보고 최종 조정할 수 있다.
- 미리보기 발 판정은 반지름10px 원이다. 본 게임 HeroActor의 사각형 hw9/hh6 판정과 동일하다는 의미가 아니다. 최종 통합에서는 기존 판정과 맞추고, 큰 보스의 반경도 따로 검사한다.
- playerSpawn, enemySpawns, portals는 배치 후보. 실제 방 ID, 진행 순서 또는 새 출구를 자동 생성하지 않는다.
- landmarks의 baked-closed-gate-needs-variants는 그림에 닫힌 문이 남아 있는 자리다. 현재 열린 통로로 처리하면 안 된다.

[RoomSceneLayout.java](../../core/src/main/java/com/yongsa/world/RoomSceneLayout.java)는 좌표 변환과 원형 발 경계 검사를 제공한다. 현재 메인 게임에서는 자동 호출하지 않는다.

## Claude의 실제 통합 지점

1. 최신 구현과 비교한 뒤, 지역별 대표 방 하나에 먼저 배경과 경계를 연결한다. 캠프 및 기존 방 연결 그래프의 진행 조건을 보존한다.
2. WorldMap.buildRoom은 지금 직사각형 타일을 만들고 Room.inside도 사각형을 검사한다. 실제 방 형태를 바꿀 때 roomAt, solid, 몬스터/광맥 생성, 경로 탐색, 구르기, 투사체와 골렘 벽 충돌까지 같은 경계 기준으로 맞춘다.
3. WorldMap.buildLink/makeDoor는 현재 셀의 좌우·상하 중앙에 3타일 문을 배치한다. 그림의 통로는 임의 위치이므로 기존 중앙 문 계산에 그대로 연결하지 않는다. 방별 출입구와 실제 링크를 대응시키고, 부족한 방향은 배경 변형을 제작한다.
4. 기존 WorldRenderer의 바닥·벽·자동 횃불을 이 배경 위에 중복해서 그리지 않는다. 배경에는 이미 명암과 불빛이 들어 있으므로 기존 전체 어둡게 하기 패스를 그대로 두 번 적용하지 않는다.
5. 열린 통로만 portals에 들어 있다. 성채의 뒤 철문·오른쪽 붉은 봉인과 탑 뒤 봉인은 상태별 문 그림이 더 필요하다. 최종 전당 뒤 거대한 문은 현재 장식이다.
6. 불·조명·문양과 벽의 빛나는 광석은 정적 배경에 포함돼 있다. 현재 미리보기에서는 정적이다. 채굴해 사라지는 광맥은 별도 자산으로 배치하거나 해당 부분을 더 비운 배경이 필요하다. 정적 광맥 위에 같은 광맥을 중복 배치하지 않는다.
7. 카메라의 최초 목표는 그림 전체보다 실제 전투 공간과 적의 공격 예고가 보이는 범위다. 이 미리보기는 전체 그림 FitViewport이고, 본 게임의 추적 카메라와 다르다. 특히 마족병 사거리·보스 탄막은 실제 플레이로 확인해야 한다.

## Java 미리보기 실행

JDK17에서 저장소 루트 기준:

```powershell
.\gradlew.bat :lwjgl3:dist
java -cp lwjgl3/build/libs/yongsa-game-0.1.0.jar com.yongsa.lwjgl3.RoomScenePreviewLauncher
```

1~4: 지역 변경 · WASD/방향키: 이동 · Tab: 경계 표시 · R: 시작 위치 · Esc: 종료.

이 실행기는 GameSession이나 저장 파일을 만들지 않는다. 전투나 문 이동이 없는 자산/좌표 검토용이다. 기본 게임 실행 진입점은 변경하지 않았다.

자동 GL 캡처:

```powershell
java -cp lwjgl3/build/libs/yongsa-game-0.1.0.jar com.yongsa.lwjgl3.RoomScenePreviewLauncher --capture design/natural-dungeons/captures
```

## 검증

- JDK17 빌드 성공, 전체 테스트 47개 통과(기존43 + 새4).
- 새 테스트: PNG 실제 크기와 좌표 일치, 플레이어/적/출입구의 발 배치, 상하축 전환과 월드 원점 이동, 오목한 모서리의 발 관통 방지, 모든 배치 후보까지의 연결 경로.
- 실제 libGDX GL 렌더링 캡처 8장: 4개 배경 × 용사 표시/경계 표시.
- 경계는 디자인 초안이며 본 게임 전투·방 전환·긴 플레이 검증을 대신하지 않는다.
- 한글 경로의 Gradle/JDK17 테스트 worker 문제는 기존 로컬 영문 classpath init-script로 우회했다. 게임 빌드 설정은 바꾸지 않았다.

PNG는 내장 image_gen으로 생성/편집했고 이후 리사이즈·수작업 픽셀 편집 없이 원본을 보존했다. 고정 격자·제한 팔레트 네이티브 도트 원본을 의미하지 않는다.
